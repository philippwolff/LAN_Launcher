LAN PARTY LAUNCHER – KURZANLEITUNG
Stand: 31.10.2026

1. PROJEKT / GITHUB
Repository: https://github.com/philippwolff/LAN_Launcher
Lokaler Projektordner (Beispiel): C:\Projekte\LAN_Launcher\LAN_Launcher
GitHub Desktop: "Fetch origin" und "Pull origin" laden Änderungen herunter.
Eigene Änderungen: "Commit to main" und "Push origin" hochladen.
WICHTIG: Hochgeladene Spiele und Serverdaten NICHT in Git committen.

2. VORAUSSETZUNGEN
Windows, .NET 10 SDK (für Entwicklung/Build), GitHub Desktop.
Der Launcher ist eine WPF-Anwendung in C#; der Server nutzt ASP.NET Core.

3. SERVER STARTEN (ENTWICKLUNG)
Eingabeaufforderung (cmd) im Projektordner öffnen:
  set "LANLAUNCHER_AdminKey=HIER_EIGENEN_SCHLUESSEL_EINTRAGEN"
  dotnet run --project src/LanLauncher.Server
Der Admin-Schlüssel wird nur für die Serverlaufzeit gesetzt.
Serveradresse auf dem gleichen PC: 127.0.0.1:8080
Für andere PCs: LAN-IP des Server-PCs und Port 8080 verwenden.
Server mit Strg+C beenden.

4. SERVER ALS EXE STARTEN
Im Projektordner "Server-EXE-erstellen.cmd" doppelklicken.
Die erzeugte EXE liegt unter Server\LanLauncher.Server.exe.
"Server-starten.cmd" startet sie und fragt nach dem Admin-Schlüssel.
Der Ordner Server\ ist lokal und wird nicht nach GitHub übertragen.

5. LAUNCHER STARTEN (ENTWICKLUNG)
Zweite Eingabeaufforderung im Projektordner:
  dotnet run --project src/LanLauncher.Client
Server-IP/Port und Benutzernamen eintragen, dann "Verbinden".
Über "⚙ Einstellungen" die Standardordner für Installation und Download
festlegen. Die Einstellungen werden pro Windows-Benutzer gespeichert unter:
  %LOCALAPPDATA%\\LANLauncher\\settings.json
Standardinstallation: %LOCALAPPDATA%\\LANLauncher\\Games
Standarddownload: %USERPROFILE%\\Downloads
Bei "Herunterladen und installieren" wird der Standardinstallationsort
automatisch genutzt; ZIP-Spiele erhalten einen Unterordner mit Spielnamen.
Downloads für die Installation werden zunächst als temporäre .part-Dateien
im Standarddownloadordner abgelegt und nach Verarbeitung entfernt.
"Nur Paket herunterladen" öffnet weiterhin den Speichern-Dialog, der im
eingestellten Downloadordner startet.
Die Spielerübersicht zeigt derzeit verbundene Benutzer.

6. ADMIN / SPIELE HOCHLADEN
Den gleichen Admin-Schlüssel wie beim Serverstart im Launcher eintragen.
Spielname und Version angeben, "ZIP/EXE hochladen" auswählen.
Alternativ Dateien in den Serverordner Games\Inbox kopieren,
"Server-Inbox prüfen" klicken und "Aus Inbox importieren" wählen.
ZIP/EXE-Upload und Download zeigen ein Fortschrittsfenster mit Prozenten.
"Abbrechen" beendet eine laufende Übertragung; beim Schließen des Clients
erscheint eine Sicherheitsabfrage (Ja = schließen und Übertragungen\nabbrechen; Nein = Launcher geöffnet lassen). Unvollständige
Downloads werden als .part-Dateien gespeichert und bei Abbruch gelöscht.
Bereits vorhandene .part-Dateien von älteren Versionen ggf. manuell löschen.
Das Hauptfenster und das separate Spielaktionsfenster sind größer.
Die Spielebibliothek ist alphabetisch sortiert. Wenn keine Auswahl aktiv ist,
wird das zuletzt geöffnete Spiel markiert, sonst das alphabetisch erste.
Ein Spiel in der Bibliothek anklicken: Es öffnet sich ein Aktionsfenster
mit einem eigenen Aktionen-Block: "Starten", "Herunterladen und installieren",
"Nur Paket herunterladen"
und "Vom Server löschen (Admin)". Ein Doppelklick auf das bereits
markierte Spiel öffnet das Aktionsfenster erneut.
"Starten" öffnet die bekannte Spiel-EXE. Ist noch keine hinterlegt,
kannst du einmalig eine lokale EXE auswählen. Die Zuordnung wird in
den lokalen Einstellungen gespeichert. Nach ZIP-Installation wird eine
erkannte/ausgewählte EXE automatisch als Startpfad hinterlegt.
NEU: "Herunterladen und installieren" lädt das gewählte Spiel herunter.
- ZIP: Installationsbasisordner auswählen; ZIP wird automatisch in einen
  neuen Unterordner mit dem Spielnamen entpackt. Anschließend sucht der
  Launcher nach EXE-Dateien. Bei einer EXE wird deren Start angeboten;
  bei mehreren EXE-Dateien wählst du die richtige aus. Vor dem Start
  muss die Ausführung ausdrücklich bestätigt werden.
- EXE: Installationsbasisordner auswählen; nach dem Download fragt der
  Launcher ausdrücklich, ob der normale Installationsassistent gestartet
  werden soll. Eine stille/unbeaufsichtigte Installation erfolgt nicht.
- Unvollständige Downloads werden entfernt. Bereits vorhandene Dateien
  im Installationsordner werden nicht überschrieben.
- Die Installation registriert derzeit noch keinen Spielstart im Launcher.
SPIEL LÖSCHEN (ADMIN): Spiel in der Bibliothek anklicken, im Popup
"Spiel vom Server löschen (Admin)" anklicken und Warnung bestätigen.
Dies entfernt den Bibliothekseintrag und das Paket aus Packages\ dauerhaft.
Der Admin-Schlüssel muss gültig sein. Bereits heruntergeladene Dateien
auf anderen PCs sowie Dateien in Inbox\ bleiben erhalten.

7. SPEICHERORTE AUF DEM SERVER
C:\LAN_Launcher_Server\Games\
  Packages\  = hochgeladene ZIP-/EXE-Pakete
  Inbox\     = Dateien für manuellen Import
  games.json  = gespeicherte Spieleinformationen
Der Server erstellt benötigte Ordner automatisch.
Wurden Spiele vor der Umstellung hochgeladen, müssen Packages und
games.json aus dem bisherigen Storage-Ordner einmalig kopiert werden.
Den alten Ordner erst nach erfolgreicher Prüfung löschen.

8. WICHTIGE HINWEISE / NOCH OFFEN
- EXE-Installationsassistenten können nach Download und Bestätigung gestartet
  werden; deren Installationsablauf und Zielverzeichnis bestimmt der Installer.
- ZIP-Archive werden automatisch entpackt und können nach Bestätigung
  eine enthaltene EXE starten; automatischer Spielstart ohne Rückfrage,
  Installationserkennung und Versionsabgleich folgen später.
- Ganze entpackte Spieleordner werden noch nicht automatisch importiert.
- Admin-Zugriff ist derzeit über einen Schlüssel geschützt; HTTP im LAN
  ist nicht verschlüsselt. Nur in einem vertrauenswürdigen LAN einsetzen.
- Nur Spielepakete verteilen, für die entsprechende Nutzungsrechte bestehen.
- Bei Fehlern die vollständige Konsolenausgabe bzw. Fehlermeldung sichern.

PFLEGE DIESER ANLEITUNG
Diese Datei liegt im GitHub-Repository und wird bei künftigen Änderungen
am Launcher von uns mit aktualisiert. Nach Änderungen über GitHub Desktop
erneut "Fetch origin" / "Pull origin" ausführen.

HINWEIS SMART APP CONTROL (WINDOWS):
Die separat veroeffentlichte Server-EXE kann durch Smart App Control blockiert werden.
Server-starten.cmd startet daher das Serverprojekt mit dem .NET 10 SDK ueber
'dotnet run --project src\LanLauncher.Server\LanLauncher.Server.csproj'.
Dafuer muss das .NET 10 SDK installiert sein. Das Skript fragt den Admin-Schluessel
ab und setzt LANLAUNCHER_AdminKey nur fuer diesen Startvorgang.
Smart App Control muss nicht deaktiviert werden.

STANDARD-INSTALLATIONSORDNER (CLIENT):
Bei neuen Einstellungen ist C:\LAN_Launcher_Server\Games der Standard-Installationsordner.
Bereits gespeicherte Installationsordner bleiben unveraendert und koennen
ueber Einstellungen angepasst werden.

WINDOWS-98-DESKTOP-ICON FUER CLIENT:
Das Client-Projekt verwendet automatisch das Icon
src\LanLauncher.Client\Assets\LAN_Party_Client.ico, sobald die Datei dort liegt.
Den Assets-Ordner ggf. erstellen und die bereitgestellte ICO-Datei hineinkopieren.
Danach Client neu bauen/veroeffentlichen. Das EXE-Symbol und das Symbol einer
neuen Desktop-Verknuepfung werden entsprechend gesetzt.

EXE-INSTALLATION MIT ZIELORDNER:
Vor dem Start einer heruntergeladenen EXE erscheint ein Dialog mit dem
gewuenschten Installationsordner und der Auswahl des Installer-Typs:
- Unbekannt / manuell: keine Zielordner-Parameter; im Assistenten selbst waehlen.
- NSIS: /D=Zielordner (als letztes Argument, ohne Anfuehrungszeichen).
- Inno Setup: /DIR=Zielordner.
Der Typ wird je Spiel gespeichert. Bitte immer den im Installer angezeigten
Zielordner kontrollieren: Nicht jeder Installer unterstuetzt diese Parameter.
Der heruntergeladene EXE-Installer bleibt im Downloadordner, nicht im
eigentlichen Spielinstallationsordner. ZIP-Dateien werden direkt entpackt.

CLIENT-EXE IM PROJEKTORDNER ERSTELLEN:
Nach Fetch origin / Pull origin im Ordner src\LanLauncher.Client die Datei
Client-EXE-erstellen.cmd per Doppelklick starten. Sie erstellt einen
Windows-x64-Single-File-Release-Build und kopiert die EXE als
src\LanLauncher.Client\LAN_Party_Client.exe in den gewuenschten Ordner.
Anschliessend LAN_Party_Client.exe per Doppelklick starten.
Voraussetzung: .NET 10 SDK. Das Icon wird eingebettet, wenn
Assets\LAN_Party_Client.ico existiert. Smart App Control kann selbst
erstellte, nicht signierte EXE-Dateien weiterhin blockieren; dann
stattdessen 'dotnet run --project src\LanLauncher.Client' verwenden.
Die EXE ist ein lokales Build-Ergebnis und wird nicht auf GitHub gespeichert.

KORREKTUR CLIENT-EXE-ABSTURZ (WPF):
Bei der bisherigen komprimierten Single-File-Version konnte beim Start
System.DllNotFoundException in WPF (SetWindowLongPtrWndProc) auftreten.
Client-EXE-erstellen.cmd erzeugt daher jetzt eine eigenstaendige
Mehrdateien-Version im Ordner src\LanLauncher.Client\LAN_Party_Client.
Die startbare Datei heisst dort LAN_Party_Client.exe.
WICHTIG: EXE nicht einzeln aus dem Ordner herauskopieren; die DLLs und
weiteren Dateien muessen daneben liegen. Fuer eine Desktop-Verknuepfung
die EXE im Unterordner als Ziel verwenden.
Die alte EXE direkt im Projektordner wird beim Erstellen entfernt.

AUTOMATISCHE DESKTOPVERKNUEPFUNG:
Client-EXE-erstellen.cmd erstellt nach erfolgreichem Publish automatisch
die Verknuepfung "LAN Party Client" auf dem Desktop des angemeldeten
Windows-Benutzers. Ziel ist die EXE im LAN_Party_Client-Unterordner,
Arbeitsverzeichnis ist derselbe Ordner; das EXE-Icon wird verwendet.
Eine bestehende gleichnamige Verknuepfung wird aktualisiert.
Falls das Anlegen fehlschlaegt, bleibt die EXE nutzbar und das Skript
zeigt eine Warnung an. Keine Administratorrechte erforderlich.

AUTOMATISCHE INSTALLER-ERKENNUNG:
Nach dem EXE-Download prueft der Client Versionsinformationen und typische
Kennungen im Installationsprogramm (NSIS / Inno Setup). Ein erkannter Typ
wird im Installationsdialog automatisch vorausgewaehlt und kann manuell
geaendert werden. Fuer 0ad / 0 A.D. wird NSIS vorausgewaehlt, falls
keine Kennung erkannt wird. Bei unbekannten Installern bleibt die
manuelle Auswahl (oder die zuvor gespeicherte Auswahl) erhalten.
Die Erkennung ist nicht fuer jeden Installer garantiert; Zielpfad im
Assistenten weiterhin kontrollieren.

WINDOWS-98-DESIGN:
Der Client verwendet jetzt eine einheitliche, Windows-98-inspirierte
Oberflaeche: grauer Hintergrund, Tahoma-Schrift, kantige Schaltflaechen,
klassische Eingabefelder und blaue Titelflaeche im Hauptfenster.
Die Styles gelten fuer Hauptfenster, Spielaktionen, Einstellungen,
EXE-Installation und Downloadfortschritt. Die echte Windows-Titelleiste
bleibt vom Betriebssystem gesteuert. Nach Pull origin die
Client-EXE-erstellen.cmd erneut ausfuehren.

AUTOMATISCHE SPIEL-EXE-ERKENNUNG:
Beim Klick auf Starten sucht der Client, sofern keine gueltige EXE
gespeichert ist, im konfigurierten Installationsordner unter
<Installationsordner>\<Spielname> und dessen Unterordnern nach
passenden EXE-Dateien. Setup-, Uninstall-, Update- und Hilfs-EXEs
werden nach typischen Namen ausgeschlossen. Eindeutige Treffer werden
zur Bestaetigung angezeigt und nach Zustimmung gespeichert.
Wenn keine eindeutige EXE gefunden wird, startet der manuelle
Dateidialog bereits im Installationsordner des Spiels.
Auch nach ZIP-Entpackung wird diese Erkennung angewendet.

SPIELEINSTELLUNGEN IM SPIELAKTIONEN-FENSTER:
Im Fenster Spielaktionen gibt es jetzt die Schaltflaeche "Einstellungen".
Dort kann die Start-EXE fuer das ausgewaehlte Spiel angesehen und
ueber "Durchsuchen..." geaendert werden. Die Dateiauswahl beginnt
im aktuellen EXE-Ordner oder im Installationsordner des Spiels.
"Spiel-EXE automatisch suchen" prueft den Installationsordner erneut.
Mit "Speichern" wird der EXE-Pfad dauerhaft nur fuer dieses Spiel
hinterlegt. Ein leeres Feld entfernt die Zuordnung.
Nach Fetch origin / Pull origin den Client neu erstellen.

SPIELEBIBLIOTHEK: SCHWARZE SCHRIFT UND SPIEL-ICONS
Die Spielnamen in der Bibliothek werden schwarz dargestellt, auch
wenn ein Eintrag ausgewaehlt ist. Links neben dem Namen zeigt der
Client nach Moeglichkeit das kleine Windows-Icon der hinterlegten
Spiel-EXE an. Ist noch keine EXE hinterlegt, wird im
Spielinstallationsordner nach einer eindeutigen EXE gesucht.
Ohne gefundene EXE bleibt das Icon leer.
Nach Fetch origin / Pull origin Client-EXE-erstellen.cmd erneut starten.
